# Detailed Refactoring Analysis for Tonstores Catalog Hub

## 1. Exact Duplicates - Refactoring Approaches

### 1.1 debugLog Function
**Current Pattern:**
```typescript
const debugLog = (...args: any[]) => {
  if (import.meta.env.DEV) {
    console.log(...args);
  }
};
```

**Refactoring Suggestion:**
Create a shared utility file at `src/utils/debug.ts`:
```typescript
export const debugLog = (...args: any[]) => {
  if (import.meta.env.DEV) {
    console.log(...args);
  }
};
```

Then import it in all files where it's currently duplicated:
```typescript
import { debugLog } from '../utils/debug';
```

### 1.2 calculatePercentChange Function
**Current Pattern:**
```typescript
const calculatePercentChange = (current: number, previous: number) => {
  if (previous === 0) {
    return current === 0 ? 0 : 100;
  }
  return ((current - previous) / previous) * 100;
};
```

**Refactoring Suggestion:**
Add this function to a shared utilities file such as `src/utils/analytics.ts` or `src/utils/math.ts`:
```typescript
export const calculatePercentChange = (current: number, previous: number) => {
  if (previous === 0) {
    return current === 0 ? 0 : 100;
  }
  return ((current - previous) / previous) * 100;
};
```

### 1.3 .catch(console.error) Pattern
**Current Pattern:**
```typescript
.trackEvent('event_name').catch(console.error);
```

**Refactoring Suggestion:**
Create a utility function in `src/utils/errorHandling.ts`:
```typescript
export const safeTrack = (trackingPromise: Promise<any>) => {
  return trackingPromise.catch(console.error);
};

// Or, more generally:
export const safePromise = <T>(promise: Promise<T>, fallback?: (error: any) => void) => {
  return promise.catch(error => {
    console.error(error);
    if (fallback) fallback(error);
  });
};
```

## 2. Near-Duplicates - Refactoring Approaches

### 2.1 Form Handler Functions
**Pattern:** Similar handleSubmit, handleChange functions across multiple forms

**Refactoring Suggestion:**
Create a generic form handling hook in `src/hooks/useFormHandler.ts`:
```typescript
type FormHandlerOptions<T> = {
  onSubmit: (data: T) => Promise<void>;
  onError?: (error: Error) => void;
  onSuccess?: () => void;
};

export const useFormHandler = <T>(options: FormHandlerOptions<T>) => {
  const handleSubmit = async (data: T) => {
    try {
      await options.onSubmit(data);
      options.onSuccess?.();
    } catch (error) {
      console.error('Form submission error:', error);
      options.onError?.(error as Error);
    }
  };

  return { handleSubmit };
};
```

### 2.2 try/catch Error Handling Patterns
**Pattern:** Similar try/catch blocks for API calls

**Refactoring Suggestion:**
Create a utility function in `src/utils/errorHandling.ts`:
```typescript
export const withErrorHandling = async <T>(
  operation: () => Promise<T>, 
  errorMessage: string,
  onError?: (error: Error) => void
): Promise<T | null> => {
  try {
    return await operation();
  } catch (error) {
    console.error(errorMessage, error);
    trackError(error, 'GenericHandler', errorMessage);
    onError?.(error as Error);
    return null;
  }
};
```

### 2.3 trackError/trackEvent Patterns
**Pattern:** Similar event tracking and error logging across components

**Refactoring Suggestion:**
Create specialized hooks for different tracking scenarios:

1. In `src/hooks/useTracking.ts`:
```typescript
export const useApiTracking = (componentName: string) => {
  const trackApiCall = async (operation: string, apiCall: () => Promise<any>) => {
    try {
      const result = await apiCall();
      await trackEvent(`${operation}_success`, { component: componentName });
      return result;
    } catch (error) {
      await trackError(error, componentName, operation);
      throw error;
    }
  };

  return { trackApiCall };
};
```

2. Generic tracking utilities in `src/utils/tracking.ts`:
```typescript
export const trackAsyncOperation = async (
  operationName: string,
  component: string,
  operation: () => Promise<any>
) => {
  try {
    const result = await operation();
    await trackEvent(operationName, { component });
    return result;
  } catch (error) {
    await trackError(error, component, operationName);
    throw error;
  }
};
```

## 4. Implementation Strategy

### Phase 1: Create Shared Utilities
1. Create `src/utils/debug.ts` with the debugLog function
2. Create `src/utils/errorHandling.ts` with error handling utilities
3. Create `src/utils/tracking.ts` with tracking utilities

### Phase 2: Update Individual Files
1. Replace all instances of duplicated functions with imports
2. Update error handling patterns to use new utilities
3. Update tracking patterns to use new utilities

### Phase 3: Create Specialized Hooks
1. Create hooks for common patterns identified
2. Update components to use these hooks

### Phase 4: Testing and Validation
1. Ensure all functionality remains the same
2. Run tests to verify no regressions
3. Update any tests that might be affected by the changes

## 5. Benefits of Refactoring

- **Maintainability:** Changes only need to be made in one place
- **Consistency:** Standardized error and tracking behavior across the application
- **Readability:** Cleaner code with less repetitive patterns
- **Reliability:** Centralized error handling reduces chances of inconsistent behavior
- **Performance:** Potential optimization opportunities in shared utilities
